# agentic-research — 工程级深度调研

把一个开放式技术问题，做成**有信源、有对比、有落地结论**的调研报告，并按用户习惯归档到飞书。本技能沉淀自大量真实调研实践，核心是「先拆解、再并行取证、后交叉验证、最终落地企业内场」的范式。

## 触发判断

命中任一即用：

- 动词信号：深度调研 / 深入调研 / 全方位对比 / 技术选型 / 出白皮书 / 出 SOP / 给一份技术方案 / 系统讲解
- 链接信号：给一篇文章 / 博客 / 微信公众号 / GitHub 仓库 / 飞书 wiki，要求解读、提炼方法论、具象化到生产实践
- 决策信号：A 与 B 怎么选、为什么业界普遍用 X、如何从 0 搭建 Y

不要用于：一句话速答、纯写代码、纯翻译创作。

## 黄金准则（来自实践教训）

1. **有理有据，绝不编造**。每个关键结论必须能追溯到具体信源（文章 / 仓库 / 官方文档 / 公司内部 wiki）。无据的判断要显式标注为"推断"。
2. **企业内场优先落地**。结论不能停在"业界怎么做"，必须回答"在公司内部生产环境怎么落地"——明确语言栈、框架栈、Infra 约束（例：SERVER 限定 Golang、Agent 框架限定开源 Eino）。调研早期就要主动追问或确认这些约束。
3. **内外信源并取**。公网（业界前沿）+ 公司内部（onepage / 技术方案 / wiki / 字典）双线检索，内部信源往往是落地的关键。
4. **默认归档到飞书**。调研产出默认沉淀为飞书文档，默认「深度图文版」（图文结合）。调研做完主动归档，不必等用户单独要。

## 工作流

### 第 1 步 — 拆解问题（不可跳过）

把开放问题拆成 3–6 个可独立取证的子问题。例如「Workflow vs 自建 Agent 怎么选」拆成：定义与边界 / 能力对比维度 / 成本与可维护性 / 适用场景判据 / 真实案例 / 落地建议。

同时锁定三件事并在必要时向用户确认：
- **落地约束**：语言、框架、部署环境、内外网
- **产出形态**：报告 / 白皮书 / SOP / 技术方案 + 脚手架代码
- **输出风格**：纯文本 / 图文结合 / Canvas（默认图文结合的深度版）

### 第 2 步 — 并行取证

每个子问题独立取证，**并行**而非串行：

- **公网检索**：`web_search` 找前沿文章 → `web_builtin_fetch` 抓原文（搜索摘要不算信源，必须读原文）。JS 站点或抓取失败时切 `mira-remote-browser`。
- **公司内部检索**：`retrieve_company_context` 查内部 onepage / 技术方案 / wiki / 飞书字典 —— 落地相关结论几乎都靠它。
- **代码仓库解读**：给了 GitHub / 内部 GitLab 仓库时，clone 下来读关键路径（入口、核心模块、数据流），而非只看 README。
- **指定材料**：用户给了文章/wiki 链接，先完整读，再延展检索佐证。

子问题多、单条 transcript 大时，用 Agent 工具并行分发（一个子 agent 负责一个子问题），主线只做汇总，避免上下文爆掉。详见 `scripts/research_plan.py` 生成的取证矩阵。

### 第 3 步 — 交叉验证与对比

- 关键结论至少两个独立信源印证；冲突时摆出分歧并给出倾向性判断 + 理由。
- 对比类问题用结构化对比表（维度 × 方案），每格给依据。
- 区分「业界通行做法」与「适配本企业内场的做法」。

### 第 4 步 — 落地化

- 给出在公司内场的具体落地路径（技术栈、模块划分、协议选型）。
- 技术方案类产出附**脚手架代码**放文档附录。
- SOP / 白皮书类给出从 0 到 1 的可执行步骤与可度量指标。

### 第 5 步 — 归档飞书

- 默认生成飞书文档，深度图文版（关键架构/流程配图，用 `generate_pictures` 或白板）。
- 用 `lark-doc` / `lark-wiki` 技能写入；用户指定归档到个人 wiki 则用 `lark-wiki`。
- 正文内联引用信源 `[[标题]](url)`，不在文末堆引用。

## 报告结构模板

1. **结论先行（TL;DR）**：3–5 条最关键判断 + 落地建议
2. **背景与问题拆解**：调研目标、企业内场约束、子问题清单
3. **逐子问题分析**：每个子问题独立成节，业界做法 + 信源 + 内场适配
4. **对比与选型**：结构化对比表 + 选择判据
5. **落地方案**：技术栈、模块/协议设计、风险点；技术方案附脚手架代码
6. **附录**：信源清单、术语表、（可选）评测集/指标定义

## 评测/benchmark 类专项要点

调研测试评测、benchmark 搭建时额外覆盖：
- **评测集形态**：参考开源评测集（如 SWT-Bench、TheAgentCompany 等）的字段设计与评测标准；数据量大时截断取样（如前 100 条）观察 schema
- **可量化指标**：准确率 / 覆盖率 / 通过率 / 误报漏报 / 成本与时延等客观可度量维度
- **Agent 化流程**：哪些评测环节可由 agent 自动完成，如何减少人力投入

## 配套脚本

- `scripts/research_plan.py`：输入一个调研主题，输出「子问题 × 取证手段 × 信源类型」的取证矩阵，作为第 1–2 步的脚手架。用法见脚本头部注释。
