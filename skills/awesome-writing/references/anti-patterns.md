# 常见写作坏味道

这是快速扫描清单，不是机械替换表。命中后先回到四个原点：它是让事实失真、让读者更费力、让判断不可信，还是让人读不下去？若不伤害读者，保留作者原风格。

## 事实没想清楚

| 坏味道 | 表现 | 修改方向 |
|---|---|---|
| 空话判断 | “具有重要意义”“奠定坚实基础” | 补具体动作、机制或结果；补不出就删 |
| 模糊归因 | “专家认为”“行业数据显示”但无来源 | 标真实来源，或删除主张 |
| 广告腔 | 宏大、夸张、情绪化但无信息 | 改成中性事实和边界 |
| 过度外推 | 用单次样本、局部结果宣称普遍有效 | 标明样本、条件和适用范围 |
| 假装全知 | 未查证却写成确定事实 | 写“未验证/待确认”，说明缺什么证据 |

## 读者要自己拼结构

| 坏味道 | 表现 | 修改方向 |
|---|---|---|
| 结论埋得太深 | 先讲历史和过程，当前判断在后面 | 当前结论前置，历史按时间线或附录承接 |
| 标题不兑现 | 标题讲配置，正文讲愿景或别的主题 | 改标题，或把内容移到对应章节 |
| 线性堆砌 | 多对象、多约束、多步骤挤成长段 | 按读者任务拆成列表、表格、步骤或小节 |
| 主线被备查打断 | 完整契约、长命令、历史明细夹在通读路径中 | 主线留结论和最小步骤，其余归同篇备查区 |
| 历史当前混陈 | 旧编号、旧状态和现行结论放同一格 | 标明时间点；当前结论与历史映射分开 |
| 假问题 | 标题或设问后并不回答 | 改成真实读者问题，或删除装饰句 |
| 无信息重复 | 同一待办、状态或口号在多处逐字复述 | 一处定义，其他位置引用或删除 |
| 误删强化 | 把案例回扣、不同视角解释也当重复 | 判断删除后是否损失理解或信任；损失则保留 |

同一案例先展示问题、后展示解决后的变化，是帮助理解的强化；把同一待办在摘要、状态卡和结尾原样写三遍，才是无信息重复。

## 判断不可信

| 坏味道 | 表现 | 修改方向 |
|---|---|---|
| 数字裸奔 | 只有数量，没有表名、时间、分母、口径 | 补来源和统计范围；不同分母分开 |
| 状态混用 | 已验证、待补证、不适用、建议写成一类 | 用一致状态词，并说明判定依据 |
| 职责不清 | “只做 A”与正文出现 B 读取/执行互相矛盾 | 分开定义创建与读取、生产与消费、当前与历史 |
| 否定式拔高 | “不仅仅是……更是……” | 直接陈述真实差异 |
| 金句替代论证 | 好听但换成任何主题都成立 | 换成具体机制和边界 |
| 谄媚与聊天残留 | “好问题”“希望有帮助” | 直接回答任务 |

保留防止误用的真实职责边界：“索引只读取知识，不修改源文件”说明操作范围；“它不仅是工具，更是一场革命”没有说明具体差异，应改为事实。

## 载体不适配

| 坏味道 | 表现 | 修改方向 |
|---|---|---|
| 表格列与内容不匹配 | 一格里塞多个对象，或列名与内容口径不一致 | 按比较最小单位成行，列名对应读者问题 |
| 无收益的交互壳 | 增加 HTML/动画，既未降低理解成本，也无原生组件无法满足的版式需要 | 按 `rich-media-playbook.md` 的“HTML 与交互”重新选型 |
| 图没有读者任务 | 图很精致但与章节问题无关 | 删除无关装饰，或移到全局位置并说明地图用途 |
| 图文互相复述 | 图画出结构，正文逐字念图 | 图承载结构，正文讲机制、结论和例外 |
| 录屏无摘要 | 无时长、无大纲、无文字步骤 | 补时长和关键步骤；不能只靠视频讲手册 |
| 降级不说明 | 画板变图片、交互变静态却仍称原能力 | 保留内容并明确可编辑性或交互能力下降 |

## 风格与阅读体验

| 坏味道 | 表现 | 修改方向 |
|---|---|---|
| 并列信息挤成正文墙 | 多个可独立查阅的约束藏在长段中 | 拆成可扫读结构；连贯因果链不按句数或屏数硬拆 |
| 视觉位置不稳定 | 同类状态、证据、边界每次位置不同 | 固定同类信息的可预测位置 |
| 粗体制造假重点 | 普通词大量加粗 | 只加粗结论、关键判断或需要扫读的词 |
| 格式无功能 | 引用块、emoji、分隔线、边框只做装饰 | 按 `rich-media-playbook.md` 的“排版与注意力”区分语义与装饰，保留有效的作者写法 |
| 机器内容不可复制 | 命令被拆成多段内联文本 | 用完整代码块，保证可复制 |
| 标题无法导航 | 多个并列小节只用加粗段落，目录中不可定位 | 可寻址单元使用真实标题或宿主等效导航 |
| 抽象无锚点 | 新机制直接堆术语 | 用读者已知概念类比，再落回真实机制 |

## 使用例外

以下情况不要机械修改：

- 原文的事实、数据、代码、专有名词、引用链接和用户补充内容。
- 作者有意的短句、节奏、重复或口语，只要它增强表达且不误导。
- 真实存在的三项、固定命令、协议符号、平台限制。
- 用户风格样例中稳定存在、且不与事实准确性冲突的写法。
- 作者已有但仍然高效的图、表、画板和交互。
