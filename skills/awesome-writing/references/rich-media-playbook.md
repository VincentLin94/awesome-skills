# 载体选择手册

载体只解决一个问题：怎样让读者更容易理解、查证或执行。没有理解收益，就不要为了“丰富”“高级感”增加载体。

按需要查阅：[主线与备查](#选择顺序) · [载体选择](#载体清单) · [排版与注意力](#排版与注意力) · [图文分工](#图文分工) · [降级](#降级原则)。

## 选择顺序

先分主线与备查，再选段内载体。

- **主线**：读者不看就无法理解结论的信息，放正文，并结论前置。
- **备查**：字段、命令、原始样例、长 SOP、历史明细、可机械查阅的清单，放同节表格、代码块、折叠块或同篇附录。
- 不要为了清爽把理解主线必需的解释拆到子文档；同步块只用于复用已经独立存在、且有单一事实源的内容。

## 载体清单

### 段落

用于定义、因果链、背景解释和需要连续推进的论证。多个可独立理解的约束挤在一段时，拆成列表或表格；连贯论证不要按句数硬拆。

### 列表

用于同一层级、可平行扫读的少量并列项。同级条目保持相同语法角色和相近粒度；不要把步骤、原因、风险混在一个无序列表里。

### 表格

用于多个对象在多个维度上的对照。表头是维度，不是长句；单元格放可比较的要点，不塞完整段落。

若表格是为了查字段，列应直接对应读者要查的字段；不要把“读取对象”和“生产对象”、“已验证”和“待补证”混在同一格而不说明视角。

### 代码块与内联代码

- 命令、配置、协议、完整样例放代码块；能执行的代码标语言，纯结构示意标 `text`。
- 字段名、命令、路径、枚举和可复制字面量用内联代码；普通中文概念不用代码样式。
- 长样例若只供复制或备查，收进折叠块/附录，并在正文说明它与必做步骤的关系。

### 图与画板

以下内容优先用图：系统链路、架构关系、状态流、生产/消费闭环、多角色协作、复杂拓扑。

- 全局图帮助读者建立全篇地图，优先放在文首摘要附近；放在章节中时要明确“此为全篇地图”。
- 章节内图只回答本章问题，不承担跨章导航。
- 图承载节点、关系、方向和边界；紧邻文字只解释关键机制、结论和例外。
- 作者已有图默认保留。图与正文重复时，优先改写文字或移动位置，不轻易删图。
- 简单流程可使用轻量图；面向交付的复杂系统图应使用宿主当前支持的可编辑画板能力。若该能力不可用，明确降级为静态图，不假装可编辑。

### 图片与录屏

- 图片用于界面事实、结果对照、空间位置或图面信息，图片本身比文字更直接时。
- 录屏只用于静态截图讲不出的多点位连续操作，如群内卡片流转、多窗口操作、连续点击反馈。
- 单条命令、单个页面、单个配置项不配录屏。
- 录屏附近必须标时长，并给内容大纲、关键步骤或文字摘要，保证不播放也能完成理解和检索。
- 产品宣传片、以视频为主体的教程另按其体裁处理，不受此规则约束。

### HTML 与交互

HTML 的理由是交互能降低理解成本，或原生组件无法满足交付所需的版式：

1. 同一组对象要在多个角色或视角间切换。
2. 后续内容随条件或状态分支变化，静态展开会造成文字墙。
3. 大图需要按泳道、路径或中心对象聚焦。
4. 需要离线固定版式或跨平台呈现，且宿主原生组件不能同等表达。

原生组件能同等表达并满足交付要求时，优先原生组件。离线报告需要固定布局时，静态 HTML 也成立；普通并列清单用列表就能读清时，不加无信息增益的 hover、动画或交互壳。

交互内容必须自包含，有标题和一句话读图引导；脚本不可用时，核心结论仍可通过静态文字、表格或 `noscript` 兜底获得。

### Callout 与分栏

Callout 只承载一种语义：关键定义、红线、操作提示、事实账本、待验证边界等。不要把普通正文整段塞进提示框制造“重点感”。

分栏用于真实对照或互补关系，如“做什么/不做什么”“现状/方案”“证据/结论”。没有对应关系时顺排。

## 排版与注意力

格式帮助读者区分主线、旁注、重点和机器内容。保留样稿中有效的排版习惯，按信息负荷安排密度；引用原话、命令和协议符号保持原样。

- **引用块**：用于引用原话、标来源或补充条件，让读者知道这段与正文的关系。主线论证用普通正文推进，不为缩进效果把整章装进引用块。
- **分隔线**：用于大主题切换，让读者知道上一段论证已结束。段落内的因果推进靠标题与自然间距衔接，不每两段插一条线。
- **留白**：用段落、标题、列表、图表之间的块级间距表现层次，不靠连续空行或堆横线撑版面；具体间距交给宿主渲染。
- **emoji 与提示样式**：用作类型标签时，同类语义全篇保持一致，让读者学会一次就能分辨。可以不用 emoji；使用时不规定必须是哪套图标，也不把每段都变成提示框。
- **强调与色彩**：加粗结论、关键差异或扫读锚点；先用字重和留白分层，需要区分状态或对象时再加颜色、边框。强调密度由内容决定，不设每屏数量或配色数上限。

正例：引用块标“来源：接口合同”，正文紧邻说明该来源支持什么结论；同一提示图标始终表示定义。

反例：把核心结论缩进只为“显眼”，同一图标一会儿表示定义、一会儿表示错误，或给每段普通词加粗。若强调无法让读者更快找到重点，就应删减。

## 图文分工

| 载体承载 | 文字承载 |
|---|---|
| 节点、层级、关系、流向、空间位置、状态变化 | 为什么这样设计、读者应得出的结论、例外和边界 |
| 一眼看清的全局快照 | 可检索的术语、命令、来源、步骤细节 |
| 操作过程中的真实界面与反馈 | 操作前提、失败处理、验收口径 |

坏例：图已画出 A→B→C，正文又按顺序复述 A、B、C。

好例：图画出 A→B→C，正文说明 B 的异步解耦决定了 A 失败不阻塞 C。

## 降级原则

目标平台不支持某载体时，保留信息结构而不是保留实现形式：

- 画板不可复制 → 静态图加图注，并说明不可编辑。
- 交互不可用 → 静态图、表格或分步骤文字。
- 录屏不可播放 → 关键截图加文字步骤。
- 表格过宽 → 明确横向查看，或改为按对象分组的卡片；不要把列压到逐字换行。

交付前在真实目标平台或可获得的预览中检查。拿不到预览时写明未验证，不把 XML 解析成功或本地结构检查当作视觉验收。
