# 把性格写成行为

以 `assets/ip-config.json` 中的性格、关系和语言为准。先选一件具体的小事，再让两只用不同反应把它完成；避免在故事里直接解释性格标签。

## 组合方法

- 需要观察与判断：给卡卡一个可核实的小细节，给皮皮一个能缓和节奏的回应。
- 需要热闹与幽默：先建立正常动作，再出现小失误，最后用一个真实反应收住；两只轮流出糗。
- 需要温暖与陪伴：用撑伞、递茶、挪位置、等一下等行为表达，台词只补充画面没有表达的信息。
- 需要认真推进：两只都能做事；按具体场景安排分工，不把性格写成固定能力高低。

以下短场景用于演示写法，不是已发生的背景故事。

| 场景 | 行为 | 台词示例 |
| --- | --- | --- |
| 下雨 | 卡卡把叶伞挪向皮皮，皮皮把茶杯往中间递 | 卡卡“往这边点儿。”皮皮“茶也给你留着。” |
| 茶烫 | 皮皮刚喝就缩嘴，卡卡不动声色地把杯子移开一点 | 卡卡“它还冒着气呢。” |
| 出发 | 卡卡检查绳结，皮皮把小包放稳 | 皮皮“都在，慢慢走。” |
| 复盘 | 两只把石子排开，留出一颗重新看 | 卡卡“这颗，咱再瞅一眼。” |

## 页面形象与反馈

让角色动作回应真实状态：等待时轻微观察，空状态时留一张安静陪伴的画面，成功时有一个短庆祝。操作失败的文字先讲清原因和下一步，角色提供温度；需要用户判断的信息用清楚的话表达。

页面中的角色动作不应挡住内容和操作。由交互触发短反馈，遵从减少动态效果的系统偏好。已有“卡皮潜水站”是页面应用案例，其巡游、按铃和盖章用途不自动进入人物传记。

## 交付检查

删去画面和动作已经说明的旁白。读者应能从短场景看出两只的不同反应与相互照顾；文案脱离聊天历史也能理解。用户指定方言或更强的搞怪风格时再增加程度，保持角色身份与温和关系。
