# Capybara

## 先确定角色，再制作资源

1. 读取 [IP 配置](assets/ip-config.json)。它是角色身份、性格、关系、画风和默认属性的唯一设定来源；区分作者明确设定、已有作品依据、整理设定与尚未设定。
2. 根据任务选择下面的参考，只加载相关资料与图片。图像任务至少查看所涉及角色的立绘；双角色任务分别核对两只。完成条件是能够明确指出每只角色的识别特征、目标画风和本次动作。
3. 保留配置中的身份特征，用本次要求补充场景、姿势、情绪、服饰与尺寸。把生成工具需要的角色描述写完整；工具未必认识名字，也未必能读取本地文件。
4. 生成或配置后，按目标用途检查成品。完成条件是角色未混淆、风格一致、动作与道具成立、输出文件可用。用户要实际资源时交付文件；用户要提示词或配置时交付相应内容。

| 任务 | 按需读取 |
| --- | --- |
| 立绘、头像、换装、背景、封面 | [生成方法](references/generation.md)；配置中对应的角色参考；必要时查看画风参考 |
| GIF、视频、动作修订 | [生成方法](references/generation.md)中的动作分支；[资源入口](references/resources.md)中的动作图集；按需定位原动画 |
| 性格、故事、台词、页面反馈 | [角色表达](references/storytelling.md)；配置中的性格、关系与语言 |
| 配置读取或修改 | 直接使用 IP 配置；按下一节区分临时变化与永久设定 |
| 查找、复用原图、GIF、视频 | [资源入口](references/resources.md)；通过 [素材查询脚本](scripts/media.py)检索索引 |

## 属性与设定变更

- 常规创作在现有配置上推导；生日、年龄、性别、身高、亲属关系等空值保持未设定，除非任务确实要求补充。
- 节日服装、临时职业、动作情绪和场景布局写入本次产物，保留原配置。用户明确要求修改 IP 设定时，更新 `assets/ip-config.json` 的相应字段，并检查受影响的参考图或素材入口。
- 现有角色立绘与配置共同约束身份。历史素材可提供画法或构图；其中的服饰、别名、头饰不自动成为新角色或永久属性。
- 配置中的色值来自早期角色代码，服务于矢量与属性配置。水彩成品的色温、纹理和毛色层次以参考图为准。

## 资源体积与读取

先使用内置 WebP 参考；需要逐帧检查、高清输出或源视频时，再从原件索引定位素材。原件路径相对于使用方项目根目录，Skill 内资源路径相对于本 Skill。

```sh
python3 "<Skill目录>/scripts/media.py" bundled
python3 "<Skill目录>/scripts/media.py" find "水彩自然动作9款 喝茶"
python3 "<Skill目录>/scripts/media.py" resolve "capybara-emoji/水彩自然动作9款/02-喝茶烫嘴.gif" --project-root "<项目根目录>"
```

Skill 被单独迁移后，内置图、设定和生成方法仍可使用。原项目不在时，只说明对应原件不可用，继续使用内置参考完成可以完成的部分。

新增资源时优先保留能改变后续制作的代表图、角度或关键帧。大图、GIF、视频与压缩包留在项目素材目录，通过 `assets/media-catalog.json` 登记相对路径；同内容原件只保留一条记录及其多个位置。内置图片保留头饰、五官、轮廓、毛感与道具关系，裁切和转码来源记录在索引中。

面向用户只交付任务所需产物与简短说明。不要把素材索引、配置字段或制作过程当作成品内容。
