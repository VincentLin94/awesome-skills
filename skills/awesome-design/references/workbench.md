# 工作台与细节尺度

将个人视觉语言应用到导航、密集列表和详情工作区。来源是用户的 VeriFlow 实际界面与本地设计库，已用当前源码作对照。此处吸收空间组织和交互机制；默认颜色、字体角色与材料体系仍由 [视觉规则](visual-language.md) 统一定义。

## 风格如何保持一致

| 轴线 | 暖纸图解 | 密集工作台 | 保持的共同规则 |
| --- | --- | --- | --- |
| 材质 | 暖白微纹理承托图形 | 实体表面，纹理仅保留在预览 | 文字清晰，触感不覆盖操作 |
| 排版 | 少量宋体展示标题 | 无衬线标题、对齐的短标签与数据列 | 字体角色明确，层级由尺寸／重量／间距共同建立 |
| 强调 | 朱红标出关键关系 | 同一强调 token 标出当前入口或主要动作 | 一套品牌强调色，状态另有语义 |
| 空间 | 同尺度比较与结论邻近 | 跨对象分组、同对象内部连续 | 距离表达关系，稳定位置支撑理解 |
| 反馈 | 局部关系显现 | 标记移动、就地展开、固定宽度加载 | 一次动作对应一次可理解的变化 |

本分支复用现有主题。借鉴 VeriFlow 的暖橙指示点时，默认转成当前页面的强调色；借鉴其立体图标时，保留少量入口的材质辨识度，普通操作继续使用同一套线性图标。金属、玻璃与粒子不是该工作台分支的默认装饰。

## 连续画布与分组

同一层级的全局导航与页面可共享画布底色，选中状态由单个导航项承担。顶栏是否固定、是否有分隔线取决于实际滚动和遮挡关系，不把玻璃、底板和外边框全部叠上去。

同一业务对象的标题、元数据、控制区与表格共享一个 Surface，内部用细分隔或空白过渡。多个独立对象才用组间留白、共同边界与必要的定位线。分组线不能同时被解释为失败标记；需要强调当前对象时带明确选中态。

```css
.awesome-design .ad-workgroups {
  display: grid;
  gap: var(--ad-space-6);
}
.awesome-design .ad-workgroup {
  background: var(--ad-surface);
  border: 1px solid var(--ad-rule);
  border-radius: var(--ad-radius-panel);
}
.awesome-design .ad-workgroup__section {
  padding: var(--ad-space-4) var(--ad-space-6);
  background: transparent;
}
.awesome-design .ad-workgroup__section + .ad-workgroup__section {
  border-block-start: 1px solid var(--ad-rule);
}
```

这段骨架只负责静态分组；交互边界仍按控件对比度验证。表格保留 table 语义和数据对齐；需要横向滚动时将滚动范围限定在表格容器，而不是裁掉列或让整页横向漂移。

列表标题先识别对象，第二行承载 ID、时间等次信息。共享外链与成员信息集中在组头，子项只呈现差异。高频动作就近且保持固定位置；加载图标、计数和展开文案预留尺寸，展开不推动无关控件。

## 密度有适用对象

已知以鼠标键盘为主的桌面工作台，可从 32–40px 控件、14px 正文、12–13px 辅助信息开始；28px 仅用于明确的紧凑控件，并检查实际命中区、间距和焦点。它们是有条件的密度选择，不覆盖本技能面向触摸的 44px 建议。

先减少重复标题、嵌套容器和冗余元信息，再缩字号。保留桌面宽屏的横向扫描能力；如果目标产品明确仅服务桌面，不为假设中的移动工作流重构主要布局，窄屏仍需保证内容与入口可达。新建面向多设备的网页则继续完整响应式设计。

## 图标按职责绘制

**品牌入口：** 少量相同家族的具象图标或材质图形，用于辨认产品区域。保持光源方向、投影软硬、边缘亮度和视觉体积一致；图标缩小后首先保住轮廓。静态 PNG/SVG 足以承担的入口不引入独立 Three.js 场景。

**功能概念：** 需要中尺寸语义徽章时，可用同一轮廓语言和少量浅底色区分概念；这层只有确有识别收益时才加入。它不等于每个列表项都要一个彩色底板。

**操作控件：** 搜索、复制、关闭、展开等 16–24px 图标优先单色轮廓、统一笔画、`currentColor` 与完整可访问名称。阴影与纹理从这一层退出，让命中区和动作清楚。

品牌入口可以有细腻材质，操作图标保持简洁；二者通过色温、重量和边缘一致性属于同一系统。不要将来源中的暖橙霓虹边、完整 QA 徽章或品牌标识直接复制到无关产品。

## 焦点与命中区

复合输入由一个可见字段边框承接焦点。外壳使用 `:focus-within` 时，内部 input 不再叠加第二圈光晕；但键盘仍须有清晰的实际聚焦对象。内含独立复制／清除按钮时，按钮保留独立命中区与 focus-visible，不能把整组看起来聚焦当作按钮焦点。

可打开详情的行中，复选框、链接、复制按钮各自可操作，不触发行主动作；可用主标题链接或独立查看按钮实现明确语义。hover、focus 和 selected 是不同状态，不能把鼠标经过表现为已经选中。

## 分类、状态与定位分开

“属于什么”“正在做什么”“结果如何”是不同维度。默认先使用短标签、位置与形状区分，只有需要快速扫描的状态使用色彩。某步骤已完成不自动意味着其业务结果通过；图形必须忠实反映已有状态，而非由样式推导事实。

同一语义色在标签、进度与时间线复用。时间线可用中性细轴、对齐时间和状态点保持秩序；选择一个节点时只突出相关关系，布局与其他节点位置保持稳定。多色阶段标签只在产品确需分类时使用，不作为通用装饰色板。

## 来源边界

本文件的方法参考作者提供的 VeriFlow 私有设计库及其实际工作台，并与源码中的导航、列表、焦点和图标实现进行对照。公共仓库只保留可复用的视觉机制，不分发私有站点链接、内部源码、品牌图标或业务数据。

设计库与实际界面可能存在差异，因此继承的是连续画布、清晰分组、图标分工与输入反馈的原则，具体尺寸和时间需由目标项目的现状与实测确定。采用这些方法不依赖 VeriFlow 仓库或账户。
