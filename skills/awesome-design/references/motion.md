# 交互与动效

目标：输入立即可见，物体跟手，松手后的运动继承当前位置与速度，下一次输入可立即改变方向。此处吸收 apple-design 的连续性原则，并保留 frontend-design 对动效必要性和单一表现点的要求。

## 按状态选择实现

| 变化 | 优先实现 | 关键细节 |
| --- | --- | --- |
| 按压、选中、边界、颜色 | CSS `:active`、`data-state`、明确 transition 属性 | 按下即反馈，点击／释放提交；离开可取消 |
| 明确起终点的入场与退出 | CSS 或 WAAPI | 从触发源方向出现，退出回到相同空间关系 |
| 布局变化 | 原生重排；必要时 FLIP 或已有布局动画库 | 先读后写，处理缩放文字、滚动和快速反向操作 |
| 拖拽、吸附、弹性回弹 | Pointer Events + 保留 x/v 的弹簧 | 手指直接控制时不附加滞后过渡，松手后再模拟 |
| 三维运动 | 现有渲染循环、四元数／受约束角度 | 帧率无关；静止与离屏停止；DOM 控制替代手势 |

CSS 过渡可在普通反向状态变化时继续使用；它不能自动提供手势抓取、速度继承等完整物理语义。已有成熟组件能满足任务时优先使用；只有具体机制需要时才引入或自建弹簧。

## 从输入到结果

每个组件明确 idle、pressed/dragging、settling、settled，以及 cancel 的结果。状态模型以位置／选中值为事实，视觉是派生结果。不要为了动画完成而锁住输入，也不要等待退出动画才响应下一次有效操作。

指针实现：

1. `pointerdown` 只接受合适按钮和主指针；从当前 presentation value 记录抓取偏移。需要捕获时使用 `setPointerCapture`。
2. 用短时间窗口估计速度，统一为 CSS px/s。若松手前已经停住，应得到接近 0 的速度，不能沿用最后一次快速移动的速度。
3. `pointermove` 更新当前值；渲染合并到下一帧。横向拖动区域用 `touch-action: pan-y` 留出页面纵向滚动；二维专用画布才局部使用 `none`。
4. `pointerup` 根据释放速度投影到受约束的落点，然后选择合法吸附点；`pointercancel`、失去捕获、页面隐藏有明确恢复路径。
5. 相同操作提供可见按钮、原生 range 或键盘替代。焦点归属与视觉选中分开，不让重渲染意外移走焦点。

抓取点在物体边缘时，不要把物体中心跳到指针。drag 中的用户选择／hover 干扰应只在拖动区域控制；不能为一个拖拽全局关闭无关控件。

## 弹簧与单位

阻尼比 ζ=1 表示临界阻尼；它不是 Motion 中数值为 1 的 `damping`。物理参数满足 `damping = 2 × ζ × sqrt(stiffness × mass)`。速度单位跟随动画值的单位：平移 px/s，角度 rad/s 或 deg/s，必须保持一致。

普通控件先用无明显过冲的响应；动量释放确实需要时才加入弹性。交互时间约 120–280ms 可作简单过渡起点；弹簧由物理参数决定结束，不能把 response、duration 和 settling time 混为一谈。

Motion 的不同 API 对时间单位、物理参数和 duration 参数的组合有各自定义；使用前对照项目锁定版本。`bounce: 0` 是无弹性起点，`damping: 1` 不是。设置 stiffness/damping/mass 时，不再假设 duration/bounce 同时起作用。直接操作需要确认当前值和速度确实被继承。

可复用的 [spring.mjs](../assets/web-lab/spring.mjs) 使用临界阻尼解析解，以 px 为示例单位，提供 setTarget、grab、setPosition、settle、dispose。改变目标保留当前 x/v；抓取时停止弹簧并保留位置，随后由新指针轨迹决定释放速度。它仅覆盖一维吸附，复杂滚动／手势仲裁仍优先成熟库。

封闭滑轨可通过 bounds 限制合法范围，在边界消除向外速度；这是明确的硬边界，不冒充橡皮筋效果。需要弹性边界时应同时维护原始输入与可见位移，并在重新抓取时从可见值继续，避免只压缩绘制坐标却用未压缩坐标计算抓取。

修改该模块后，在交互样本中实际检查目标反向不重置位置、重新抓取、终态停止帧、静止后释放无旧速度以及边界行为；观察最终产物，不用文档自检代替交互验证。

落点预测只负责“去哪”，弹簧负责“怎么去”。可以从 `x + v × horizon` 的有界预测开始；horizon 是经验窗口，不是 Apple 的精确模型。使用指数衰减公式时，应显式说明时间基准与速度单位，避免跨库复制常数。

## 连续性与细节

- 弹层来源稳定，transform-origin 靠近触发控件。普通退出保持几何路径一致，速度曲线依具体动作设计，不强求入场曲线的数学镜像。
- 弹簧重定向保持当前 x/v。FLIP 被打断时从当前屏幕矩形重新计算，不从旧目标重新起步。
- 使用 rAF 时间戳和 delta time；恢复后台标签时重置时钟，避免把数秒间隔一次积分。小步数值积分需要 dt 上限，解析解也需限制不合理暂停导致的视觉跳跃。
- `will-change` 只在即将运动时启用，结束后清除；不要让整页长期生成合成层。
- 页面加载不强迫所有卡片分别延迟入场。装饰循环默认静止或提供显式播放；其节奏不得影响操作就绪。

### 小范围反馈

当前导航可以由一个共享标记连续移动来表达。标记由布局事实定位，文字选中态及 `aria-current`／`aria-selected` 同时更新；字号、容器和语言变化后重新测量。小圆点、短线或轻底色选一种主手法，避免每项都增加独立光晕。高频切换保留当前视觉位置，减少动效时直接定位。

重要动作可在首次进入 hover 或键盘 focus 时出现一次短高光，完成后保持静止；同一次交互不因重渲染重放。普通列表行只需要底色或边界反馈。图标微移仅用于少量有辨识度的入口，效果不改变布局或命中区。共享焦点逻辑见 [工作台与细节尺度](workbench.md#焦点与命中区)。

详情退场时冻结最后一次有效呈现，立即停止其读取和交互，退出后释放；快速选择另一项则取消旧退出并按新 identity 呈现。不要在退出过程中先清空内容，留下移动的空壳，也不能让旧请求覆盖新选择。这类生命周期处理比增加弹跳更影响完成度。

## 减少动效与对照

CSS 与 JavaScript 都响应 `prefers-reduced-motion` 的当前值及 change 事件。减少动效时依然允许用户直接拖动／旋转自己控制的对象，但松手后的惯性、自动旋转、弹跳和大尺度镜头移动停止；状态直接落定或使用短淡变。

需要对照时可提供组件内“减少动效”开关。开关只影响本组件；系统偏好与本地开关取更保守值。静态终态包含完整信息，不能把动画关掉后留在 opacity:0。

完成前实际做：连续点两个相反目标、运动途中重新抓取、按住停顿后松手、取消拖动、键盘改变值、减少动效、组件卸载再挂载。记录哪些已经运行验证；单帧截图不能证明速度连续或达到帧率指标。
